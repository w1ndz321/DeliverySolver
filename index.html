面向配送订单-骑手分配问题的自主策略迭代系统

离线 Agent 沉淀经验库，在线 Agent 根据数据画像快速选择策略，并在时间限制内输出最优求解器。

01

数据画像

提取订单规模、骑手供给、候选密度、合单比例和接单意愿分布。

02

自主选策略

在线 Agent 基于 case profile 和经验库判断数据类型，选择最合适的候选算法。

03

自动评测诊断

对候选解做合法性、目标分数、覆盖率和失败模式诊断，只保留有效改进。

04

迭代更优算法

离线 Agent 从实验日志中探索新策略，把验证有效的规则沉淀回经验库。

PROBLEM REQUIREMENT

赛题要求

配送订单-骑手分配本质上是带约束的组合优化问题。它具有 NP-hard 特征，难点不只是找到合法解，而是在有限时间内尽可能产出更优解。

核心判断

不同场景需要不同策略

订单规模、骑手供给、候选密度、合单比例、接单意愿分布都会改变最优算法选择。固定贪心在某些场景有效，但在骑手稀缺、合单丰富或低意愿风险高的场景里可能失效。

01

为什么引入 Agent

Agent 的作用是把“人工试算法”变成自动研究过程：分析数据特征，选择候选策略，运行评测，再根据失败模式继续生成和筛选更优算法。

02

离线 Agent 沉淀经验

离线状态没有在线响应压力，可以让 Agent 反复探索策略、做消融实验、总结哪些数据类型适合哪些算法，并把结论写入经验库。

03

在线 Agent 快速决策

在线运行时有严格效率要求，因此不重新做大规模搜索，而是先生成 case profile，再从经验库快速判断数据类型并选择最合适的求解策略。

04

项目交付目标

最终交付的是一个可持续进化的 AutoResearch Agent 系统：离线自主优化算法，在线高效选择算法，在时间限制内输出当前最优 solver。

HOW AUTOSOLVER WORKS

系统架构

系统把“离线研究”和“在线求解”拆开：离线 Agent 负责探索、评测和沉淀经验，在线 Agent 只做快速画像、查经验库和调用稳定 solver。

01

离线研究 Agent

在无响应压力的环境里生成候选算法，做消融实验，记录不同场景下的收益和失败模式。

02

策略经验库

沉淀 case type、特征阈值、适用算法、风险约束和历史评测结果，形成可复用的决策依据。

03

在线决策 Agent

运行时只做轻量数据画像，从经验库判断当前数据类型，快速选出最合适的稳定策略。

04

Solver 输出层

执行已验证的算法模块，完成合法性检查和目标分数评估，在时间限制内输出当前最优解。

最终提交路径保持轻量：研究、评测和迭代在 Agent 系统中完成；OJ solver 只保留已验证的稳定求解模块。
